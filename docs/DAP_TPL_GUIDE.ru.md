## Введение

DAP TPL — мощная система обработки шаблонов, разработанная для генерации C кода в test framework DAP SDK. Предоставляет богатый язык шаблонов с переменными, условиями, циклами, макросами и многим другим.

### Ключевые концепции

- **Шаблоны** - Текстовые файлы со встроенными директивами (расширение `.tpl`)
- **Переменные** - Заполнители, заменяемые значениями
- **Конструкции** - Управляющие структуры вроде `if`, `for`, `macro`
- **Функции** - Преобразования, применяемые к переменным
- **Токены** - Внутреннее представление AST
- **Движок** - Скомпилированная AWK программа, обрабатывающая шаблоны

### Философия дизайна

- **Модульность** - Каждая функция — отдельный плагин
- **Композируемость** - Функции работают вместе без проблем
- **Расширяемость** - Легко добавлять новые конструкции
- **Тестируемость** - Полное покрытие тестами

## Туториал

### Урок 1: Ваш первый шаблон

Создайте `hello.tpl`:
```
Hello, {{NAME}}!
Welcome to {{PROJECT}}.
```

Обработайте его:
```bash
source dap_tpl/dap_tpl.sh
replace_template_placeholders hello.tpl output.txt "NAME=World" "PROJECT=DAP TPL"
```

Результат:
```
Hello, World!
Welcome to DAP TPL.
```

### Урок 2: Использование условий

Создайте `conditional.tpl`:
```
{{#if ENABLE_DEBUG}}
#define DEBUG_MODE
{{else}}
#undef DEBUG_MODE
{{/if}}
```

Обработайте:
```bash
replace_template_placeholders conditional.tpl output.h "ENABLE_DEBUG=1"
```

### Урок 3: Циклы

Создайте `loop.tpl`:
```
{{#set TYPES=int|char*|void*}}
{{#for type in TYPES}}
typedef {{type}} my_{{type}}_t;
{{/for}}
```

### Урок 4: Макросы для переиспользования

Создайте `macros.tpl`:
```
{{#macro DECLARE_GETTER}}
{{ARG0}} get_{{ARG1}}(void);
{{/macro}}

{{#call DECLARE_GETTER|int|count}}
{{#call DECLARE_GETTER|const char*|name}}
```

### Урок 5: Всё вместе

Объедините все возможности в реальном шаблоне:

```
{{#macro MOCK_FUNCTION}}
{{ARG0}} mock_{{ARG1}}({{ARG2}}) {
    {{#if ARG0 contains '*'}}
    return NULL;
    {{#elif ARG0 == void}}
    // Нет возврата
    {{else}}
    return 0;
    {{/if}}
}
{{/macro}}

{{#set FUNCTIONS=init|int|void
cleanup|void|void
get_data|char*|int id}}

{{#for func in FUNCTIONS}}
{{func|split|pipe}}
{{#call MOCK_FUNCTION|{{func|part|0}}|{{func|part|1}}|{{func|part|2}}}}
{{/for}}
```

См. [docs/examples/06_complex.tpl](examples/06_complex.tpl) для полного примера из реальной практики.

## Справочник языка

### Переменные

#### Синтаксис
```
{{VARIABLE_NAME}}
{{VARIABLE|function|argument}}
```

#### Доступные функции

**Строковые операции:**
- `trim` - Убрать начальные/конечные пробелы
- `contains|substring` - Проверить наличие подстроки
- `split|delimiter` - Разделить на части (используйте `pipe` или `newline`)
- `part|index` - Получить часть по индексу после split
- `replace|pattern|replacement` - Заменить все вхождения паттерна на замену
- `remove_suffix|suffix` - Удалить суффикс из строки

**Сравнение:**
- `ne|value` - Не равно значению
- `in_list` - Проверить наличие в списке

#### Примеры
```
{{NAME}}                          → значение NAME
{{NAME|trim}}                     → обрезанное значение
{{LIST|split|pipe}}               → разделить по |
{{LIST|part|0}}                   → первый элемент
{{VALUE|ne|0}}                    → проверить что не ноль
{{TEXT|contains|test}}            → проверить наличие "test"
```

**Примечание:** Дополнительные функции переменных могут быть доступны через расширения (например, `normalize_name`, `escape_name`, `sanitize_name` из расширений мокинга).

### Условия

#### if/elif/else

**Синтаксис:**
```
{{#if УСЛОВИЕ}}
  содержимое когда истина
{{#elif ДРУГОЕ_УСЛОВИЕ}}
  содержимое когда первое ложно, а это истина
{{else}}
  содержимое когда всё ложно
{{/if}}
```

#### Типы условий

**Булевы:**
```
{{#if VAR}}              - Истина если VAR не пустая и не "0"
{{#if !VAR}}             - Истина если VAR пустая или "0"
```

**Сравнения:**
```
{{#if VAR == value}}     - Равно
{{#if VAR != value}}     - Не равно
{{#if VAR > 5}}          - Больше
{{#if VAR >= 5}}         - Больше или равно
{{#if VAR < 5}}          - Меньше
{{#if VAR <= 5}}         - Меньше или равно
```

**Строковые операции:**
```
{{#if VAR contains 'text'}}    - Содержит подстроку
{{#if VAR matches 'pattern'}}  - Соответствует regex
{{#if VAR in LIST}}            - Есть в списке
```

**Логические:**
```
{{#if VAR1 && VAR2}}     - Логическое И
{{#if VAR1 || VAR2}}     - Логическое ИЛИ
{{#if !VAR}}             - Логическое НЕ
```

### Циклы

#### Цикл for

**Синтаксис:**
```
{{#for ПЕРЕМЕННАЯ_ЭЛЕМЕНТА in ПЕРЕМЕННАЯ_СПИСКА}}
  содержимое использующее {{ПЕРЕМЕННАЯ_ЭЛЕМЕНТА}}
{{/for}}
```

**Разделители списков:**
- Вертикальная черта: `элемент1|элемент2|элемент3`
- Перевод строки: многострочные списки

### Присваивание переменных

#### set

**Синтаксис:**
```
{{#set VAR=значение}}
{{#set VAR={{ДРУГАЯ_VAR}}}}
```

### Макросы

#### Определение макроса

**Синтаксис:**
```
{{#macro ИМЯ_МАКРОСА}}
  содержимое шаблона с {{ARG0}}, {{ARG1}}, ...
{{/macro}}
```

#### Вызов макроса

**Синтаксис:**
```
{{#call ИМЯ_МАКРОСА|аргумент1|аргумент2}}
```

#### Параметры

- `{{ARG0}}` - Первый аргумент
- `{{ARG1}}` - Второй аргумент
- `{{ARG2}}` - Третий аргумент
- и т.д.

### Включения

#### Включение шаблона

**Синтаксис:**
```
{{#include "имя_файла.tpl"}}
```

Шаблоны (расширение `.tpl`) обрабатываются рекурсивно с текущими переменными.

#### Включение обычного файла

**Синтаксис:**
```
{{#include "имя_файла.h"}}
```

Файлы не-шаблоны включаются как есть.

### Комментарии

#### Однострочные

**Синтаксис:**
```
{{! текст комментария }}
```

#### Многострочные

**Синтаксис:**
```
{{!--
многострочный
комментарий
--}}
```

Комментарии удаляются из вывода.

## Cookbook

### Рецепт 1: Генерация enum из списка

```
{{#set VALUES=SUCCESS|ERROR|PENDING|TIMEOUT}}
typedef enum {
{{#for value in VALUES}}
    STATUS_{{value}},
{{/for}}
} status_t;
```

### Рецепт 2: Условная компиляция

```
{{#if PLATFORM == linux}}
#include <linux/types.h>
{{#elif PLATFORM == windows}}
#include <windows.h>
{{else}}
#include <stdint.h>
{{/if}}
```

### Рецепт 3: Генерация объявлений функций

```
{{#macro DECLARE}}
{{ARG0}} {{ARG1}}({{ARG2}});
{{/macro}}

{{#set FUNCTIONS=int|init|void
void|cleanup|void
char*|get_name|const char* id}}

{{#for func in FUNCTIONS}}
{{func|split|pipe}}
{{#call DECLARE|{{func|part|0}}|{{func|part|1}}|{{func|part|2}}}}
{{/for}}
```

### Рецепт 4: Генерация типобезопасных обёрток

```
{{#set TYPES=int|char*|dap_list_t*}}
{{#for type in TYPES}}
{{#set TYPE_NAME={{type|replace|*|_ptr|replace| |_}}}}
typedef struct {
    {{type}} value;
    int is_valid;
} safe_{{TYPE_NAME}}_t;
{{/for}}
```

**Примечание:** Для нормализации имён, специфичной для C (например, `normalize_name`), используйте расширения мокинга.

### Рецепт 5: Условная генерация моков

```
{{#if CUSTOM_MOCKS_LIST}}
{{#for mock in CUSTOM_MOCKS_LIST}}
{{mock|split|pipe}}
{{#set FUNC={{mock|part|0}}}}
{{#set RETURN={{mock|part|1}}}}
#define MOCK_{{FUNC}} mock_{{FUNC}}
extern {{RETURN}} mock_{{FUNC}}(void);
{{/for}}
{{else}}
// Нет пользовательских моков
{{/if}}
```

### Рецепт 6: Обработка вложенных данных

```
{{#set DATA=name:string:John
age:int:30
city:string:NYC}}

{{#for entry in DATA}}
{{entry|split|:}}
{{#set FIELD={{entry|part|0}}}}
{{#set TYPE={{entry|part|1}}}}
{{#set DEFAULT={{entry|part|2}}}}

{{#if TYPE == string}}
const char* {{FIELD}} = "{{DEFAULT}}";
{{#elif TYPE == int}}
int {{FIELD}} = {{DEFAULT}};
{{/if}}
{{/for}}
```

## Инструменты командной строки

### dap_tpl.sh

Основная библиотека для обработки шаблонов.

**Расположение:** `dap_tpl/dap_tpl.sh`

#### Использование

```bash
# Подключить библиотеку
source dap_tpl/dap_tpl.sh

# Обработать шаблон
replace_template_placeholders ВХОДНОЙ_ФАЙЛ ВЫХОДНОЙ_ФАЙЛ [ОПЦИИ] ПЕРЕМЕННАЯ=ЗНАЧЕНИЕ ...
```

#### Синопсис

```
replace_template_placeholders ШАБЛОН ВЫВОД [--extensions-dir ДИРЕКТОРИЯ] ПЕРЕМЕННАЯ=ЗНАЧЕНИЕ ...
```

#### Параметры

- `ВХОДНОЙ` - Путь к входному файлу шаблона
- `ВЫХОДНОЙ` - Путь к выходному файлу
- `--extensions-dir ДИРЕКТОРИЯ` - Необязательная директория расширений
- `ПЕРЕМЕННАЯ=ЗНАЧЕНИЕ` - Присваивания переменных (можно несколько)
- `ПЕРЕМЕННАЯ=@файл` - Переменная из содержимого файла

#### Примеры

```bash
# Простая обработка
replace_template_placeholders \
    template.tpl \
    output.h \
    "MODULE=dap_core" \
    "VERSION=1.0"

# С данными из файла
echo "type1|type2|type3" > types.txt
replace_template_placeholders \
    template.tpl \
    output.h \
    "TYPES=@types.txt"

# С расширениями
replace_template_placeholders \
    template.tpl \
    output.h \
    --extensions-dir "../mocks/lib/dap_tpl" \
    "TYPE=dap_list_t*"
```

#### Переменные окружения

- `SCRIPTS_DIR` - Путь к директории dap_tpl (автоопределение)
- `TEMPLATES_DIR` - Путь к директории шаблонов (автоопределение)
- `AWKPATH` - Путь поиска для директив @include

### dap_tpl_lib.sh

Дополнительные библиотечные функции для продвинутых случаев.

**Расположение:** `dap_tpl/dap_tpl_lib.sh`

**Примечание:** Эта библиотека опциональна и предоставляет специализированные функции. Большинству пользователей достаточно `dap_tpl.sh`.

## Справочник API

### Основные функции

#### replace_template_placeholders

Главная функция для обработки шаблонов.

**Сигнатура:**
```bash
replace_template_placeholders ШАБЛОН ВЫВОД [--extensions-dir ДИРЕКТОРИЯ] ПЕРЕМЕННАЯ=ЗНАЧЕНИЕ ...
```

**Возвращает:**
- 0 при успехе
- 1 при ошибке

**Обработка ошибок:**
- Файл шаблона не найден
- Ошибка записи выходного файла
- Синтаксическая ошибка в шаблоне
- Отсутствуют обязательные переменные

## Продвинутые темы

### Создание пользовательских конструкций

См. README.md раздел "Добавление новых конструкций".

### Система расширений

Разместите пользовательские конструкции в отдельной директории и используйте:
```bash
--extensions-dir путь/к/расширениям
```

Каждая расширение должно содержать файлы `definition.awk`, `tokenizer.awk` и `evaluator.awk` (при необходимости).

### Оптимизация производительности

- Компиляция движка кэшируется в `/tmp`
- Переиспользуйте скомпилированный движок для нескольких шаблонов
- Используйте данные из файла (`@файл`) для больших наборов данных

### Отладка

Включить отладочный вывод:
```bash
# Добавьте в шаблон
{{! Debug: VAR={{VAR}} }}
```

Проверить промежуточные файлы:
```bash
# Секции AWK создают временные файлы в /tmp
ls -la /tmp/awk_script_*
```

### Лучшие практики

1. Используйте осмысленные имена переменных
2. Добавляйте комментарии для сложной логики
3. Используйте макросы для повторяющегося кода
4. Разбивайте большие шаблоны с помощью includes
5. Тестируйте шаблоны с примерными данными
6. Используйте `--extensions-dir` для пользовательских функций

### Частые ошибки

#### Неправильный keyword_len

```awk
// НЕПРАВИЛЬНО
tokenize_simple_construct(marker_text, "include", 7, ...)

// ПРАВИЛЬНО  
tokenize_simple_construct(marker_text, "include", 8, ...)
// keyword_len = length("#include") = 8
```

#### Отсутствующие кавычки в условиях

```
{{! НЕПРАВИЛЬНО }}
{{#if TYPE == dap_list_t*}}

{{! ПРАВИЛЬНО }}
{{#if TYPE == 'dap_list_t*'}}
```

## Индекс конструкций

### if

Условное выполнение.

**Синтаксис:**
```
{{#if УСЛОВИЕ}}...{{#elif УСЛОВИЕ}}...{{else}}...{{/if}}
```

**Пример:**
```
{{#if COUNT > 0}}
Элементов: {{COUNT}}
{{/if}}
```

### for

Итерация по циклу.

**Синтаксис:**
```
{{#for ПЕРЕМЕННАЯ in СПИСОК}}...{{/for}}
```

**Пример:**
```
{{#for item in ITEMS}}
Элемент: {{item}}
{{/for}}
```

### set

Присваивание переменной.

**Синтаксис:**
```
{{#set ПЕРЕМЕННАЯ=значение}}
```

**Пример:**
```
{{#set TEMP=hello}}
{{TEMP}}
```

### macro

Определить переиспользуемый фрагмент шаблона.

**Синтаксис:**
```
{{#macro ИМЯ}}...{{/macro}}
```

**Пример:**
```
{{#macro GREETING}}
Привет, {{ARG0}}!
{{/macro}}
```

### call

Вызвать макрос.

**Синтаксис:**
```
{{#call ИМЯ|аргумент1|аргумент2}}
```

**Пример:**
```
{{#call GREETING|Мир}}
```

### include

Включить шаблон или файл.

**Синтаксис:**
```
{{#include "имя_файла"}}
```

**Пример:**
```
{{#include "header.tpl"}}
{{#include "types.h"}}
```

### comment

Добавить комментарии (удаляются из вывода).

**Синтаксис:**
```
{{! однострочный }}
{{!-- много
строк --}}
```

**Пример:**
```
{{! Это не появится }}
Код здесь
{{!--
Это многострочный
комментарий
--}}
```

## Приложения

### Приложение A: Справочник функций переменных

| Функция | Синтаксис | Описание | Пример |
|---------|-----------|----------|--------|
| split | `{{VAR\|split\|delim}}` | Разделить по разделителю | `{{LIST\|split\|pipe}}` |
| part | `{{VAR\|part\|N}}` | Получить N-ую часть | `{{LIST\|part|0}}` |
| trim | `{{VAR\|trim}}` | Убрать пробелы | `{{NAME\|trim}}` |
| contains | `{{VAR\|contains\|text}}` | Проверить подстроку | `{{TYPE\|contains\|*}}` |
| replace | `{{VAR\|replace\|pat\|rep}}` | Заменить паттерн | `{{TEXT\|replace\|old\|new}}` |
| ne | `{{VAR\|ne\|val}}` | Не равно | `{{COUNT\|ne\|0}}` |
| in_list | `{{VAR\|in_list}}` | Проверка в списке | `{{ITEM\|in_list}}` |
| remove_suffix | `{{VAR\|remove_suffix\|suf}}` | Удалить суффикс | `{{TYPE\|remove_suffix\|_t}}` |

**Примечание:** Дополнительные функции (например, `normalize_name`, `escape_name`, `sanitize_name`) могут быть доступны через расширения.

### Приложение B: Приоритет операторов

1. Логическое НЕ (`!`)
2. Сравнение (`==`, `!=`, `>`, `>=`, `<`, `<=`)
3. Специальные (`contains`, `matches`, `in`)
4. Логическое И (`&&`)
5. Логическое ИЛИ (`||`)

### Приложение C: Сообщения об ошибках

| Ошибка | Причина | Решение |
|--------|---------|---------|
| "Macro 'X' is not defined" | Макрос вызван до определения | Определите макрос перед вызовом |
| "Compiled engine not found" | Отсутствует DAP_TPL_ENGINE_PATH | Установите переменную окружения |
| "Template file not found" | Неправильный путь | Проверьте путь к файлу |
| "Maximum include depth exceeded" | Слишком много вложенных включений | Уменьшите вложенность |

### Приложение D: Тестирование ваших шаблонов

```bash
# Запустить шаблон с тестовыми данными
cd dap_tpl
source dap_tpl.sh

replace_template_placeholders \
    your_template.tpl \
    /tmp/output.txt \
    "VAR1=test1" \
    "VAR2=test2"

# Проверить вывод
cat /tmp/output.txt

# Проверить результат
diff expected_output.txt /tmp/output.txt

# Запустить системные тесты (из dap-sdk/tests/)
cd ../../tests
./run.sh test-framework     # Запустить все test-framework тесты
./run.sh unit               # Запустить только unit тесты
./run.sh integration        # Запустить только integration тесты

# Или через CTest (из dap-sdk/build/)
cd ../build
ctest -L test-framework --output-on-failure
```

## Краткая справка

### Переменные
```
{{VAR}}              Простая переменная
{{VAR|func|arg}}     Переменная с функцией
```

### Управление потоком
```
{{#if УСЛО}}...{{/if}}           Условие
```
